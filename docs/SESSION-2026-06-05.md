### 8. Settlement cron was silently broken — TWO bugs
Bolivia–Corea showed market.status `settled` in DB but `settlements` table had 0 rows and leaderboard snapshots were empty. Found:

**Bug 1 — broken PostgREST join in `settleMatchMarket`:** the query used `.eq("ticket.match_market_id", market.id)` on an embed without `!inner`. PostgREST returned all 1000+ ticket_allocations in the DB with the `ticket` embed nulled out instead of the 12 belonging to that market. The cron silently received wrong data and bailed.

**Bug 2 — per-row settlement subtracted MATCH_CREDIT each time.** `computeMarketSettlements` emitted one settlement row per allocation row, calling `settleTicket` with `winningStake = row.amount if matching else 0`. For a ticket with 3 non-zero allocations, `net` was subtracted 3 × 10k = 30k. Only worked correctly for hard picks (single allocation). Every other intensity broke.

**Fix (c28cfb2):**
- Added `!inner` to the join.
- Rewrote `computeMarketSettlements` to aggregate `winningStake` by ticket and emit one settlement row per ticket. Tests still pass since they used single-allocation tickets.

After Vercel deployed + GHA cron retrigger, Bolivia–Corea got the correct DB state: Guido +15.714, oso +4.286, Bato −10.000, Mariano −10.000. Leaderboard snapshots populated correctly.

## Pitfalls / gotchas learned today

- **PostgREST embedded filters need `!inner`** when used with `.eq("embed.col", val)`. Without it, the parent rows still come through with `embed: null` and the filter silently does nothing useful.
- **`AnimatePresence mode="wait"` is picky about children.** Adding a non-motion sibling inside it can corrupt the child diff and keep siblings rendered after their conditional flips to false. Keep AnimatePresence's children to motion components only; render plain conditional UI outside it.
- **Per-allocation settlement math != per-ticket settlement math** when `settleTicket` subtracts a fixed `MATCH_CREDIT`. Aggregate winning_stake by ticket BEFORE calling the engine.
- **GHA `*/5` crons are best-effort.** Don't depend on them firing on the dot; compute on-read in the UI layer when the source data exists to derive the right view.
- **Localstorage drafts must be gated by `isEditable`.** Stale drafts on settled matches caused contradictory displays.
- **The dummy matches are the canary.** They surfaced the settlement-cron bugs that would have hit real matches the moment intensity-medium picks started settling.
